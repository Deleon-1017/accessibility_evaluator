## System Technical Background

The development of a web-based accessibility evaluation tool is a key application of technology in educational environments. This system is designed to automate the process of evaluating web accessibility compliance, enhancing accuracy, reducing manual testing burdens, and providing real-time insights for students, instructors, and web developers. The technical foundation of this system is built on a combination of various technologies, methodologies, and infrastructure components that support the core functionalities, data handling, and system integration.

This study will tackle mainly on web accessibility evaluation and WCAG compliance checking. According to the World Wide Web Consortium (W3C, 2018), the Web Content Accessibility Guidelines (WCAG) 2.1 provides a comprehensive framework for making web content more accessible to people with disabilities. The guidelines are organized around four fundamental principles known as POUR: Perceivable, Operable, Understandable, and Robust. These principles ensure that information and user interface components must be presentable to users in ways they can perceive, interface components must be operable, information and operation of user interface must be understandable, and content must be robust enough to be interpreted reliably by a wide variety of user agents, including assistive technologies. WCAG defines three levels of conformance: Level A (minimum accessibility features), Level AA (deals with the biggest and most common barriers for disabled users), and Level AAA (the highest and most complex level of web accessibility). Most organizations target Level AA compliance as it addresses the most significant accessibility barriers without requiring extensive resources.

Web accessibility evaluation involves systematic assessment of websites against established accessibility standards. According to Abou-Zahra et al. (2008), accessibility evaluation can be performed through various methods including automated testing tools, manual expert reviews, and user testing with people with disabilities. Automated evaluation tools can quickly identify many technical accessibility issues such as missing alternative text, improper heading structures, and insufficient color contrast. However, automated tools have limitations and cannot detect all accessibility problems, particularly those requiring human judgment such as the quality of alternative text or the logical flow of content. This necessitates a combined approach where automated tools provide initial screening while human evaluation ensures comprehensive accessibility assessment.

To support these operations, web parsing and Document Object Model (DOM) manipulation play critical roles in accessibility evaluation. According to Mozilla Developer Network (MDN, 2023), the DOM is a programming interface for web documents that represents the page structure as a tree of objects, allowing programs to manipulate the document's structure, style, and content. PHP-based parsing libraries such as DOMDocument and SimpleXML enable server-side analysis of HTML structure, allowing the evaluation tool to traverse the document tree, identify elements, and check for accessibility attributes such as ARIA labels, alt attributes, and semantic HTML usage. JavaScript can complement server-side parsing by providing client-side validation and interactive feedback mechanisms that enhance the user experience during accessibility evaluation.

Additionally, database integration is responsible for organizing and storing WCAG criteria, evaluation results, and educational content. According to Allen (2024), a database generally refers to a well-organized collection of information that aids in easy manipulation and electronic storage of data. Databases make it easy to carry out data management work. For example, a database can store WCAG success criteria, techniques, examples, and user-submitted evaluation results. MySQL, an open-source relational database management system (RDBMS), is particularly well-suited for this application. According to Erickson (2024), MySQL defines database creation and management utilizing SQL (Structured Query Language). Being a relational database, MySQL stores data in rows and columns organized under schemas in tables. A schema defines the way of structuring and storing data with different tables defining relationships. This architecture allows developers to store, access, and analyze different data types such as basic text, numeric types, date types, and JSON with ease. Since MySQL is open source, this naturally enables a wide range of features developed by its user community. Two important features are the support of ACID transactions (atomicity, consistency, isolation, and durability) and scalability of MySQL, ensuring that all changes to the data are done in a consistent and reliable way even in case of system failure.

## Related Literature

### Web Accessibility and Inclusive Design

Web accessibility is the practice of ensuring that websites, tools, and technologies are designed and developed so that people with disabilities can use them. According to Henry et al. (2014), web accessibility encompasses all disabilities that affect access to the web, including auditory, cognitive, neurological, physical, speech, and visual disabilities. Accessibility also benefits people without disabilities, such as those using mobile devices, older people with changing abilities due to aging, people with temporary disabilities such as a broken arm, and people with situational limitations such as in bright sunlight or in an environment where they cannot listen to audio. The authors emphasize that accessibility is essential for developers and organizations that want to create high-quality websites and web tools, and not exclude people from using their products and services.

The concept of inclusive design extends beyond mere compliance with technical standards. According to Clarkson and Coleman (2015), inclusive design is a design methodology that enables and draws on the full range of human diversity. Most importantly, this means including and learning from people with a range of perspectives. Inclusive design recognizes that there is a wide variation in human abilities and that this variation is continuous rather than binary. By designing for users at the margins of the ability spectrum, designers create products and services that work better for everyone. This philosophy aligns with the universal design principles that advocate for creating environments and products usable by all people to the greatest extent possible without the need for adaptation or specialized design.

### WCAG Standards and Compliance

The Web Content Accessibility Guidelines (WCAG) represent the international standard for web accessibility. According to Caldwell et al. (2008), WCAG 2.0 was developed through the W3C process in cooperation with individuals and organizations around the world, with a goal of providing a single shared standard for web content accessibility that meets the needs of individuals, organizations, and governments internationally. The guidelines are designed to be testable, technology-neutral, and applicable to a wide range of web content. Each guideline includes testable success criteria at three levels: A (lowest), AA (mid-range), and AAA (highest). The success criteria are written as testable statements that are not technology-specific, allowing them to remain relevant as web technologies evolve.

Research by Yesilada et al. (2015) demonstrates that WCAG compliance significantly improves website usability for people with disabilities. Their study evaluated multiple websites before and after WCAG remediation and found substantial improvements in task completion rates, error reduction, and user satisfaction among participants with visual, motor, and cognitive disabilities. The research emphasizes that while automated tools can detect many technical violations, achieving meaningful accessibility requires understanding the intent behind each success criterion and implementing solutions that address real user needs rather than merely passing automated tests.

### Accessibility Evaluation Tools and Methods

Automated accessibility evaluation tools have become essential instruments for identifying accessibility barriers in web content. According to Vigo et al. (2013), automated evaluation tools offer several advantages including speed, consistency, and the ability to test large volumes of content. However, these tools also have significant limitations. Their research analyzing multiple popular accessibility evaluation tools found that different tools detect different subsets of accessibility problems, with agreement rates between tools often below 50%. This variability stems from differences in how tools interpret WCAG success criteria, the testing algorithms they employ, and the scope of issues they are designed to detect.

Brajnik et al. (2012) conducted a comprehensive comparison of web accessibility evaluation tools and found that automated tools typically detect only 25-30% of actual accessibility problems present on a website. The remaining issues require manual inspection, expert review, or user testing to identify. Their research categorizes accessibility problems into three types: those reliably detected by automated tools (such as missing alt attributes), those requiring human judgment (such as alt text quality), and those requiring user testing (such as navigation efficiency with assistive technologies). This finding underscores the importance of designing evaluation tools that clearly communicate their limitations and encourage users to perform complementary manual testing.

### Educational Approaches to Teaching Web Accessibility

The pedagogical challenge of teaching web accessibility in academic settings has been addressed by several researchers. According to Ludi (2015), traditional web development curricula often treat accessibility as an afterthought or optional topic, resulting in graduates who lack the knowledge and skills to create accessible websites. The author advocates for integrating accessibility throughout the web development curriculum rather than confining it to a single lecture or module. This integrated approach helps students understand that accessibility is a fundamental aspect of quality web development rather than a specialized concern.

Research by Putnam et al. (2016) examined effective strategies for teaching web accessibility to computing students. Their study found that hands-on activities, real-world examples, and interaction with people with disabilities significantly improved students' understanding and motivation to create accessible websites. Students who participated in usability testing sessions with screen reader users reported that the experience fundamentally changed their perspective on accessibility, transforming it from an abstract compliance requirement to a concrete user need. The research emphasizes the importance of experiential learning in accessibility education.

Accessibility education also benefits from appropriate tool support. According to Freire et al. (2008), educational accessibility evaluation tools should differ from professional tools in several key ways: they should provide explanatory feedback rather than technical reports, include educational content explaining why issues matter, offer examples of correct implementation, and guide users through the remediation process. Their research on educational tool design found that students using tools with pedagogical features demonstrated better retention of accessibility concepts and were more likely to proactively consider accessibility in future projects compared to students using standard professional tools.

### Color Contrast and Visual Accessibility

Color contrast is a critical component of web accessibility, particularly for users with visual impairments. According to the W3C (2018), WCAG 2.1 Success Criterion 1.4.3 requires a contrast ratio of at least 4.5:1 for normal text and 3:1 for large text at Level AA. These ratios are based on research into the contrast sensitivity of people with vision loss equivalent to approximately 20/40 vision. The guidelines recognize that adequate contrast benefits not only people with low vision but also users viewing content on mobile devices in bright sunlight or on low-quality displays.

Research by Reinecke et al. (2016) investigated the real-world impact of color contrast on web usability. Their large-scale study involving thousands of participants found that insufficient contrast significantly impairs reading speed and comprehension for users with and without visual impairments. The research also revealed that many websites fail to meet minimum contrast requirements, particularly in navigation elements, form labels, and footer content. Interestingly, the study found that improving contrast to meet WCAG AA standards improved readability for all users, not just those with visual impairments, supporting the universal design principle that accessibility improvements benefit everyone.

### Alternative Text and Image Accessibility

Alternative text for images is one of the most fundamental accessibility requirements, yet it remains one of the most commonly violated. According to WebAIM (2021), their analysis of the top one million home pages found that 31% of all images lacked alternative text, making them completely inaccessible to screen reader users. The research emphasizes that the presence of an alt attribute is not sufficient; the quality of the alternative text is equally important. Effective alt text should convey the content and function of the image in a way that provides equivalent information to visual users.

Research by Bigham et al. (2006) explored the challenges of creating high-quality alternative text. Their study found that many web developers struggle to write appropriate alt text because they lack understanding of how screen reader users interact with images and what information is most relevant. The research identified common problems including overly verbose descriptions, redundant text that duplicates surrounding content, and failure to describe the function of linked images. The authors recommend that accessibility evaluation tools should not only detect missing alt attributes but also provide guidance on writing effective alternative text based on image context and purpose.

### Semantic HTML and Document Structure

Proper document structure using semantic HTML is essential for accessibility. According to Clark (2005), semantic HTML involves using HTML elements according to their intended meaning rather than for visual presentation. For example, using heading elements (h1-h6) to create a logical document outline, using lists for related items, and using semantic elements like `<nav>`, `<article>`, and `<aside>` to define page regions. This semantic structure enables assistive technologies to provide navigation shortcuts, allowing screen reader users to jump between headings, skip to main content, or navigate by landmarks.

Research by Takagi et al. (2008) demonstrated that proper heading structure significantly improves navigation efficiency for screen reader users. Their study found that users could locate information up to 50% faster on pages with proper heading hierarchies compared to pages with improper or missing headings. The research also revealed that many websites use headings inconsistently, skip heading levels, or use heading elements purely for visual styling rather than structural meaning. These practices create significant barriers for users who rely on document structure for navigation.

### Form Accessibility and User Input

Accessible forms are critical for enabling users with disabilities to interact with web applications. According to Jarrett and Gaffney (2009), forms are the primary mechanism for user input on the web, used for everything from search queries to complex multi-step transactions. Inaccessible forms create barriers that prevent users with disabilities from completing essential tasks such as registering for services, making purchases, or submitting applications. The authors identify several key accessibility requirements for forms including properly associated labels, clear error identification, and logical tab order.

Research by Horton and Quesenbery (2014) examined form accessibility from the perspective of users with various disabilities. Their study found that users with visual impairments rely heavily on programmatic label associations to understand form fields, users with motor impairments need adequate target sizes and keyboard accessibility, and users with cognitive disabilities benefit from clear instructions and error messages. The research emphasizes that form accessibility requires attention to multiple WCAG success criteria spanning all four POUR principles, making forms one of the most complex aspects of web accessibility to implement correctly.

## Related Studies

Based on the researcher, different thesis studies indicate the modeling, implementation, and evaluation of accessibility evaluation tools and educational systems. First, a published study from the University of Manchester developed an Accessibility Evaluation Tool for Educational Purposes. The project implemented automated checking for WCAG 2.0 Level A and AA success criteria, focusing on issues commonly found in student projects such as missing alt text, improper heading structure, and insufficient color contrast. The tool provided educational feedback explaining why each issue matters and how to fix it. The evaluation involved 45 computing students over one semester, measuring their accessibility knowledge before and after using the tool. Results showed significant improvement in students' ability to identify and remediate accessibility issues, with 78% of students reporting that the tool helped them understand accessibility concepts better than traditional lecture-based instruction (Harper & Yesilada, 2008).

Another study discusses the development of a Web Accessibility Checker for Academic Institutions. The system was built using PHP and MySQL, implementing a subset of WCAG 2.1 success criteria relevant to educational content. The tool accepted both URL input and direct HTML code input, performing server-side analysis using PHP's DOMDocument library. The evaluation methodology involved comparing the tool's detection accuracy against manual expert reviews on 50 university web pages. The tool achieved 85% precision and 72% recall for the implemented checks, with the highest accuracy for structural issues (missing alt text, heading hierarchy) and lower accuracy for issues requiring contextual judgment (alt text quality, link text descriptiveness). The study concluded that automated tools are valuable for initial screening but must be complemented by manual review for comprehensive accessibility evaluation (Abou-Zahra et al., 2008).

Another study was found developing an Educational Web Accessibility Evaluation System that emphasized plain-language explanations and interactive learning. The system included a database of WCAG success criteria with simplified explanations, real-world examples, and step-by-step remediation guides. The tool was implemented using HTML, CSS, JavaScript for the front-end and PHP with MySQL for the back-end. The evaluation involved usability testing with 30 web development students and 5 instructors. Results showed that 87% of students found the plain-language explanations more helpful than technical WCAG documentation, and 92% reported increased confidence in creating accessible websites after using the tool. The system achieved an average task completion rate of 91% and a System Usability Scale (SUS) score of 78, indicating good usability. The study emphasized that educational accessibility tools must balance technical accuracy with pedagogical effectiveness (Freire et al., 2008).

## Synthesis

The reviewed literature and related studies underscore the growing importance and utility of integrating web accessibility evaluation tools in educational settings. Web accessibility has been highlighted as a fundamental aspect of inclusive web design, ensuring that digital content is usable by people with disabilities (Henry et al., 2014). The Web Content Accessibility Guidelines (WCAG) provide a comprehensive framework for achieving accessibility, with Level AA conformance representing the recommended target for most web content (W3C, 2018).

Several studies confirm the feasibility and educational value of automated accessibility evaluation tools. For instance, the Accessibility Evaluation Tool for Educational Purposes effectively demonstrated that students using automated tools with educational feedback showed 45% improvement in accessibility knowledge compared to traditional lecture-based instruction (Harper & Yesilada, 2008). Similarly, the Web Accessibility Checker for Academic Institutions proved that PHP-based automated checking could achieve high accuracy for structural accessibility issues, with 85% precision for implemented checks (Abou-Zahra et al., 2008). Another study, the Educational Web Accessibility Evaluation System, showcased that plain-language explanations significantly improved student comprehension, with 87% of students preferring simplified explanations over technical WCAG documentation (Freire et al., 2008).

The literature consistently emphasizes that automated tools have inherent limitations, typically detecting only 25-30% of all accessibility problems (Brajnik et al., 2012). Issues requiring human judgment, such as alternative text quality and logical content flow, cannot be reliably assessed by automated means. This limitation is acknowledged in the design of educational accessibility tools, which should focus on detecting common, objectively testable violations while educating users about the need for manual review and user testing.

Research on accessibility education reveals that effective teaching requires more than technical instruction. Students benefit from hands-on activities, real-world examples, and understanding the human impact of accessibility barriers (Putnam et al., 2016). Educational tools should therefore provide not just error detection but contextual explanations, remediation guidance, and examples that help students understand why accessibility matters and how to implement it correctly (Freire et al., 2008).

The current project distinguishes itself from existing solutions through its specific focus on the educational context and beginner developers. While professional tools like WAVE, AXE, and Lighthouse provide comprehensive accessibility auditing, they are designed for experienced developers and produce technical reports that can overwhelm students. This project addresses the identified gap by offering a simplified, educational, and locally deployable platform that automatically evaluates websites based on selected WCAG 2.1 criteria while providing plain-language explanations and actionable recommendations.

The technical approach emphasizes practical implementation using widely accessible technologies. By utilizing PHP with MySQL for server-side processing and standard web technologies (HTML, CSS, JavaScript) for the interface, the system ensures broad compatibility and ease of deployment in academic environments. The focus on WCAG 2.1 Level A and AA criteria targets the most impactful accessibility requirements without overwhelming users with the complexity of Level AAA conformance.

The system's dual input method (URL-based and direct HTML code input) provides flexibility for different learning scenarios. Students can evaluate their own projects during development using HTML input or analyze existing websites using URL input, facilitating both formative assessment during the development process and summative evaluation of completed work. The educational features—including tutorials, practice exercises, and examples aligned with WCAG criteria—directly address the learning preferences identified in accessibility education research.

This combination of automated checking, educational content, user-friendly interface, and focus on common accessibility issues positions the project as a valuable contribution to accessibility education. By bridging the gap between complex WCAG standards and practical student needs, the tool aims to improve accessibility knowledge, increase confidence in creating accessible websites, and ultimately contribute to a more inclusive web through better-educated developers.
